# ChatGPT PDF provenance samples

Ten PDF files generated by ChatGPT on 8–9 November 2026, kept exactly as downloaded, for anyone who wants to check what the Content Credentials (C2PA) manifest in a ChatGPT PDF says and what is left of it after a re-save, a print or a screenshot.

Every document is fictional and says so on the page: invented company names, people, account numbers and amounts, with a "SAMPLE - NOT VALID" line on every page. Nothing here was issued by any real institution.

The write-up with the measurements: [atomara.io/blog/chatgpt-pdf-content-credentials](https://atomara.io/blog/chatgpt-pdf-content-credentials).

## Files

| File | What it is | Model named in the manifest | c2pa-python |
|---|---|---|---|
| `samples/00-statement.pdf` | Bank statement, 2 pages, DejaVu fonts, diagonal watermark | gpt-6-thinking | Valid |
| `samples/00b-statement-revised.pdf` | The same statement, revised layout | gpt-6-thinking | Valid |
| `samples/01-invoice.pdf` | Invoice, 1 page | gpt-6-thinking | Valid |
| `samples/02-receipt.pdf` | Till receipt, 1 page | gpt-6-thinking | Valid |
| `samples/03-payslip-sol-5.6.pdf` | Payslip, 1 page, made with a different model | gpt-5-6-thinking | Valid |
| `samples/04-resume.pdf` | Resume, 2 pages | gpt-6-thinking | Valid |
| `samples/05-letter.pdf` | Business letter, 1 page | gpt-6-thinking | Valid |
| `samples/06-report.pdf` | Market report with charts, 4 pages | gpt-6-thinking | Valid |
| `samples/07-image.png` | A generated receipt image; has its own manifest (`gpt-image`) | — | Valid hash, certificate rejected by c2pa-python 0.38 (missing EKU) |
| `samples/07-image.pdf` | That image placed on a PDF page by ChatGPT | gpt-6-thinking | Valid |
| `samples/08-edited.pdf` | `01-invoice.pdf` uploaded back to ChatGPT with "change the invoice date to 15 October 2026" | gpt-6-thinking, manifest inherited byte for byte from `01-invoice.pdf` | cannot open (invalid JUMBF header) |

"Valid" is c2pa-python's `validation_state` with `assertion.dataHash.match`, read with no trust list, so every file also reports `signingCredential.untrusted`. Checksums: `SHA256SUMS`.

How they were made: one account. `01`–`07` each in a new chat, the default model except `03`, with a prompt asking for a downloadable PDF of a fictional document with "SAMPLE - NOT VALID" in the footer and never mentioning signatures or metadata; `07` first came back as a PNG, and a PDF was requested after it. `08` is the edit described above. The two statements were made the evening before.

## Reading a file

```
pip install pikepdf c2pa-python
python tools/provenance.py samples/01-invoice.pdf
```

`tools/provenance.py` prints the Info dictionary, the XMP fields that matter, every embedded file with the C2PA labels found inside, the catalog's `/AF` entry, a raw-bytes versus decoded-streams count of marker strings, and, if c2pa-python is installed, the manifest and its validation result.

## Reproducing the transformations

```
qpdf samples/01-invoice.pdf out/01-qpdf.pdf
python -c "import pikepdf; pikepdf.open('samples/01-invoice.pdf').save('out/01-pikepdf.pdf')"
pdftoppm -r 144 -png samples/01-invoice.pdf out/01-raster
```

The macOS re-render paths (Quartz `CGPDFContext` for Print → Save as PDF, PDFKit `PDFDocument.write` for Preview) are in the write-up.
